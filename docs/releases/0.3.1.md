# PageBox 0.3.1

This hotfix corrects the authenticator setup flow and its notifications.

- After generating the QR, verification shows only the authenticator code and recovery-code confirmation. The password form for restarting setup appears only when **Restart setup** is opened.
- Successful activation, disabling and recovery-code replacement use the success color. Setup instructions and the mandatory-policy notice use neutral styling. Errors retain their error styling.
- Show the PageBox mark beside the QR and include the canonical PageBox icon as an optional image hint in newly generated QR codes. Authenticator apps decide whether to use that hint; existing entries keep their current icon.

The initial password confirmation remains required by Better Auth for credential accounts. TOTP secrets, account labels and issuer parameters are unchanged.

## Upgrade from 0.3.0

Select `PAGEBOX_TAG=0.3.1` and restart PageBox. No new database migrations, DNS, proxy or TLS changes are needed. Existing authenticators, recovery codes and the instance-wide 2FA policy continue working without re-enrollment.

For earlier versions, follow [the upgrade procedure](../../DEPLOYMENT-SECURITY.md).

## Validation

The regression checks cover the hidden restart form, success styling in light and dark themes, mobile enrollment and sign-in in Chromium, public availability of the icon, and preservation of the TOTP parameters when adding the image hint.
