# PageBox 0.3.0

This minor release adds authenticator-based two-factor authentication using Better Auth's official two-factor plugin.

- Set up an authenticator with a local QR code or manual setup key, verify a TOTP code, and save ten single-use recovery codes.
- Verify a second factor when signing in to either the panel or private site access. Recovery codes work if the authenticator is unavailable; replacing them invalidates the previous set.
- Require 2FA for every account from **Security** as the superadmin. First set up and verify the superadmin's own authenticator. Existing sessions must satisfy the policy, and users cannot disable required authenticators.
- Enabling or disabling 2FA ends the account's other sessions. Password changes preserve second-factor verification. The audit log records security changes without secrets or codes.

## Upgrade from 0.2.0

1. Back up PostgreSQL and the bucket, then select `PAGEBOX_TAG=0.3.0`.
2. Restart PageBox and check `/healthz` and its migration log. Migration `0010_two_factor.sql` runs at startup when migrations are enabled. Otherwise run `pnpm db:migrate` before starting the new version.
3. Open **Account → Manage authenticator** and complete setup. Reader accounts can use **Manage authenticator** on the central reader landing page.
4. Save the recovery codes before making 2FA mandatory under **Security**. Test panel and private-site sign-in with an authenticator and a recovery code.

The initial policy is optional. No DNS, proxy or TLS changes are needed when upgrading from 0.2.0. Upgrades from 0.1.x still require [the site-origin migration](../../DEPLOYMENT-SECURITY.md).

Deploy API keys remain scoped machine credentials for CI. Browser sessions must satisfy the 2FA policy. Password resets preserve the account's authenticator; recovery codes remain necessary when the device is unavailable.

The migration is additive, but 0.2.0 does not enforce the new 2FA policy. Rolling back the application to that version removes mandatory 2FA enforcement.
