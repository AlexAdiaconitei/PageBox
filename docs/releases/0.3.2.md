# PageBox 0.3.2

This hotfix restores path-based site URLs and improves authenticator enrollment and management.

- Serve every site from `<PAGEBOX_SITES_HOST>/s/<slug>/` again. 0.3.0 and 0.3.1 redirected each site to a `<slug>-<id>.<PAGEBOX_SITES_HOST>` subdomain unconditionally, which breaks every site without wildcard DNS and TLS. Per-site subdomains are now opt-in through `PAGEBOX_SITE_SUBDOMAINS` (default `false`). With it off, private sites sign in on the shared sites host, as in 0.2.
- Align the **I have saved my recovery codes** checkbox with its label using the shared checkbox style.
- Use one current-password field for **Replace recovery codes** and **Disable two-factor authentication**, with a separate button for each action. Each operation still verifies the password on the server. Disabling remains unavailable when the administrator requires 2FA.
- Show an enabled status badge and explain how to change the icon in Authy. [Authy chooses its own logo for ordinary TOTP tokens](https://help.twilio.com/articles/19753405130523); PageBox cannot force its icon through the QR image hint. In Authy, open **Settings → Accounts → PageBox → Edit logo**.

## Upgrade from 0.3.1

Select `PAGEBOX_TAG=0.3.2` and restart PageBox. No new database migrations, DNS, proxy or TLS changes are needed. Leave `PAGEBOX_SITE_SUBDOMAINS` unset to keep `/s/<slug>/` URLs; set it to `true` only with wildcard DNS and a wildcard certificate for `*.<PAGEBOX_SITES_HOST>`. Existing authenticators, recovery codes and the instance-wide 2FA policy continue working without re-enrollment.

For earlier versions, follow [the upgrade procedure](../../DEPLOYMENT-SECURITY.md).
