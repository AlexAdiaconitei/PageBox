```bash
pnpm install
cp .env.example .env
cp .env.local.example .env.local      # host-side overrides for the compose services
docker compose up -d postgres minio   # dependencies only
pnpm dev
```

Then open **http://pagebox.localhost:5173** for the panel and
**http://pages.localhost:5173** for the sites.

Plain `localhost` answers 404 on purpose: PageBox routes by hostname, and a request that is
neither host is not its business.

## Why there are two env files

`.env` holds container hostnames, which only resolve inside the compose network.
`.env.local` points the same variables at the published ports and is loaded after it.

Both are read by the `dev` and `db:*` scripts through Node's `--env-file-if-exists`. **Vite
does not put `.env` into `process.env`**, so without that flag the app starts and then
refuses to serve, which looks like a configuration bug and is not one.

## Scripts

| Command            | Does                                         |
| ------------------ | -------------------------------------------- |
| `pnpm dev`         | the app, with both env files loaded          |
| `pnpm check`       | `svelte-check` over the project              |
| `pnpm test`        | the unit tests, offline                      |
| `pnpm db:generate` | writes a new migration after a schema change |
| `pnpm db:migrate`  | applies pending migrations                   |
| `pnpm db:studio`   | Drizzle Studio against the dev database      |

## The integration suite

Use Docker and install Chromium, then run the isolated stack:

```bash
pnpm exec playwright install chromium
pnpm build
node scripts/test-stack.mjs
```

The runner creates its own PostgreSQL, MinIO, proxy and temporary directory, chooses test
credentials and removes the fixtures on exit. It never uses the development database or
homelab. It runs HTTP, concurrency and real-browser tests with a database pool of one.

Use scripts/seed-demo.mjs only with disposable data and explicit PAGEBOX_E2E_EMAIL and
PAGEBOX_E2E_PASSWORD. It takes the superadmin seat and resets its fixture account. The
standalone test runner supplies those variables itself.

## Built on

SvelteKit 2 with Svelte 5 on `adapter-node`, Postgres through Drizzle, S3 through the AWS
SDK, better-auth for sessions and deploy tokens, Tailwind 4, and optionally Valkey once
there is more than one replica. Node 22+.
