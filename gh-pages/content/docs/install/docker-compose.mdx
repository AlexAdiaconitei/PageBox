description: The standalone stack — app, Postgres, MinIO, and optionally Traefik and Valkey.
---

The compose file brings its own database and object store and pulls a published image, so an
empty directory with `docker-compose.yml` and a `.env` in it runs. Point it at your own
Postgres and S3 when you want to keep what is on it.

```yaml
image: ghcr.io/alexadiaconitei/pagebox:${PAGEBOX_TAG:-latest}
```

`PAGEBOX_TAG` in your `.env` pins the version — `0.1.0`, or `0.1` to follow the patches of
one minor. Pin it on anything you care about: `latest` moves on the next release, and
`pull_policy: always` means a restart is enough to pick that up. To run the checkout instead
of a release, replace that line with `build: { context: . }`.

## The four profiles

```bash
docker compose up -d                     # app + postgres + minio
docker compose --profile cache up -d     # + valkey
docker compose --profile proxy up -d     # + traefik, routing both hostnames on :80
```

| Profile | Adds | Needed when |
| ------- | ---- | ----------- |
| *(none)* | app, Postgres, MinIO | always |
| `cache` | Valkey | more than one replica — the app refuses to start otherwise |
| `proxy` | Traefik | you want `http://pagebox.localhost/` to work directly |

Without the proxy profile the app is on `http://localhost:3000` and you address the two
hosts with a header:

```bash
curl -H "Host: pagebox.localhost" http://127.0.0.1:3000/healthz
curl -H "Host: pages.localhost"   http://127.0.0.1:3000/
```

With it, `*.localhost` resolves to `127.0.0.1` on most systems and both hostnames work in a
browser.

## What the container does on boot

Neither Compose nor Dokploy has a release phase, so the container does it itself, in order:

<Steps>
<Step>
### Applies pending migrations
Under a Postgres advisory lock, so several replicas starting at once cannot race.
</Step>
<Step>
### Creates the S3 bucket if it is missing
MinIO and Garage alike. If the key is not allowed to create buckets, create it first.
</Step>
<Step>
### Creates the first superadmin
Only when the instance has no users at all, from `BOOTSTRAP_ADMIN_EMAIL` and
`BOOTSTRAP_ADMIN_PASSWORD`, flagged `must_change_password`.
</Step>
</Steps>

Any failure exits the process rather than serving half-configured traffic. Both the
migration and bucket steps can be switched off with `PAGEBOX_MIGRATE_ON_START` and
`PAGEBOX_ENSURE_BUCKET_ON_START` if you would rather run them yourself.

<Callout type="info" title="Once anyone exists, the bootstrap variables stop doing anything">
A restart must not reopen a closed account. That also means a forgotten superadmin password
has no route back through the interface — recovery is
[`scripts/set-password.mjs`](/docs/operate/access#recovery) with access to the deployment.
</Callout>

## Pointing it at real infrastructure

Three groups of variables, and none of them have safe defaults:

```bash
# Where it answers. Must be two different hostnames.
PAGEBOX_ADMIN_HOST=pagebox.example.com
PAGEBOX_SITES_HOST=pages.example.com
PAGEBOX_PUBLIC_SCHEME=https

# State.
DATABASE_URL=postgres://pagebox:…@db:5432/pagebox
# REDIS_URL=redis://valkey:6379            # required past one replica

# Objects. Anything that speaks S3 — MinIO, Garage, AWS.
S3_ENDPOINT=http://minio:9000
S3_ACCESS_KEY=…
S3_SECRET_KEY=…
S3_BUCKET=pagebox
S3_FORCE_PATH_STYLE=true                   # MinIO and Garage want this

# Secrets.
AUTH_SECRET=…                              # openssl rand -base64 48
BOOTSTRAP_ADMIN_EMAIL=you@example.com
BOOTSTRAP_ADMIN_PASSWORD=…
```

An invalid configuration stops the process with a list of what is wrong. Every variable is
documented in [`.env.example`](https://github.com/AlexAdiaconitei/PageBox/blob/main/.env.example),
and the ones worth knowing about are on [configuration](/docs/operate/configuration).

## Health check

`/healthz` probes Postgres and S3 and answers on any host, including an internal IP probe
that carries neither hostname. Point your orchestrator at it: a dependency outage then marks
the container unhealthy instead of letting it serve errors quietly.

## Upgrading

Deployments are immutable objects in S3 and the schema is migrated forward on boot, so an
upgrade is a new tag and a restart:

```bash
PAGEBOX_TAG=0.1.1 docker compose up -d      # or edit .env and: docker compose up -d
```

Take a database backup first if you are moving more than one version. Nothing in the object
store is rewritten by a migration.
