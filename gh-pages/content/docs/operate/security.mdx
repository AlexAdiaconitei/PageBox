---
title: Security and upgrades
description: Configure mandatory authenticator 2FA and upgrade to PageBox 0.3.0.
---

Version 0.3.0 adds authenticator-based two-factor authentication. Its release image tag is
`ghcr.io/alexadiaconitei/pagebox:0.3.2`.

## Upgrade from 0.2.0

Back up PostgreSQL and the bucket, select PAGEBOX_TAG=0.3.2, restart the app and check
/healthz and the migration log. Migration 0010 adds the authenticator table, account/session
flags and the instance policy. It runs at startup when migrations are enabled; otherwise run
`pnpm db:migrate` before starting the new version. No DNS, proxy or TLS changes are needed.

The initial 2FA policy is optional. Set up and verify the superadmin's authenticator under
**Account → Manage authenticator**, save the recovery codes, then select **Required for all
users** under **Security** if needed. Existing sessions must satisfy the policy. Test sign-in
on both hosts and private-site access. See [authenticator setup](/docs/operate/access).

Deploy API keys keep their existing CI permissions. Password resets preserve authenticators.
Version 0.2 does not enforce mandatory 2FA, so rolling back to it removes that protection.

## Upgrade from 0.1.x

Do not substitute a 0.1 image while using the new configuration.

The panel and central reader login have separate trusted origins. Uploaded content uses
`<slug-prefix>-<immutable-site-id>.<PAGEBOX_SITES_HOST>`, with the existing `/s/<slug>/`
base path. Configure wildcard DNS, a proxy route and wildcard TLS for these site hosts.
Canonical hosts must include the public port when it is not the protocol default.

Before upgrading, back up the database and bucket and stop writes. Deploy the proxy
changes and app together. Migrations run at startup. Existing deployments are not
re-extracted: rebuild or review content ingested before version 3 of the extraction rules,
which could previously retain hidden paths. Keep affected sites disabled until reviewed.

Use chosen credentials even for a local production-mode instance. Give PageBox its own
bucket-scoped storage key, keep storage administrator credentials outside the app, and
leave PAGEBOX_ENSURE_BUCKET_ON_START=false after provisioning the bucket. Keep database,
storage and direct app ports behind the trusted proxy.

Uploads have a global admission limit backed by PostgreSQL. MAX_CONCURRENT_UPLOADS defaults
to 4, MAX_UPLOAD_TEMP_BYTES to 400MB, UPLOAD_BODY_TIMEOUT_SECONDS to 60 and
UPLOAD_TIMEOUT_SECONDS to 600. All replicas must share the same limits and database.
Stop replicas and clear interrupted archives before lowering the temporary limits.

After deployment, test private login, grant removal, logout and password reset in a browser.
The full upgrade instructions and local test evidence are in DEPLOYMENT-SECURITY.md and
security-checks/README.md in the repository.
