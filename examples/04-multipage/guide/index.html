The first sync

The first run is the slow one: both sides get indexed from scratch. Everything after it reads that index and moves only what changed.

1. Index each side

# on the laptop
tern init ~/Pictures

# on the machine at home, over ssh
ssh home 'tern init ~/Pictures'

Indexing hashes every file. On a library of 40 000 photos over USB 3 it takes about eleven minutes, and it is the only time tern reads everything.

2. Look before you move

tern sync home:~/Pictures --dry-run
  → 1,204 files to send        14.8 GB
  ← 31 files to receive         402 MB
  ! 2 conflicts                 see below

Read the arrows. → leaves this machine, ← arrives on it. If the direction surprises you, stop and work out why before running it for real.

3. Run it

tern sync home:~/Pictures

It is resumable. Kill it, lose the connection, close the laptop — the next run picks up from the last completed file, not from the beginning.

Conflicts do not block the run. tern moves everything it can agree on and leaves the disagreements for you. How conflicts are resolved.
