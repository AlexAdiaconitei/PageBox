Conflicts

A conflict is both sides changing the same file since the last agreement. tern never picks a winner. It keeps both and tells you.

What it does

The file is left alone on each side and a marker is written beside it. Nothing is overwritten and nothing is deleted, which means a conflict you ignore is a conflict that stays exactly where it was.

Resolving one

Command Effect
tern resolve --mine This machine wins. The other copy is replaced on the next sync.
tern resolve --theirs The remote wins. This copy is replaced.
tern resolve --keep-both Renames one with its machine name and keeps them as separate files.

Why not just take the newest

Because modification time lies. A file copied off a card, restored from a backup or touched by a batch rename is newer than the edit you actually care about — and by the time you notice, the other copy is gone. Keeping both is slower and never wrong.
