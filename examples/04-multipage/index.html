tern

Two machines, one photo library, no third party holding the originals. tern walks both trees, works out what each one is missing, and moves only that.

What it is for

You have a laptop that takes the photos and a machine at home that keeps them. You want the second one to end up with everything, you want to be able to run it over a hotel connection, and you do not want to think about it again. That is the whole brief.

It is not a backup tool. It makes two directories agree; if you delete something on both, it is gone on both. Keep snapshots underneath it.

The shape of it

# once, on each machine
tern init ~/Pictures

# then, from either side
tern sync home:~/Pictures

The first run indexes both sides and will take a while. Every run after that reads the index and moves the difference, which on a normal week is a few dozen files.

Over a slow link: add --proofs-first and tern sends the JPEG previews before the raws, so the library is browsable long before it is complete.

What it will not do

Not this Instead
Edit or convert images It moves bytes. Your editor owns the pixels.
Resolve conflicts for you It keeps both and asks. See Conflicts.
Run as a daemon Put it in cron. A sync that runs itself is a sync you stop reading.
